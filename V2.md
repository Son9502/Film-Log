# Film Log v2 roadmap

_Written 2026-11-15, after v1 went live at [filmlog-theta.vercel.app](https://filmlog-theta.vercel.app). v1's scope and status are in [MVP.md](MVP.md)._

**Direction:** Film Log's edge is the darkroom side (development, chemistry, batches, scans), which sharing apps like Lomography don't cover. v2 deepens that first, adds the AI helpers, and only then opens the app up to sharing.

## 1. Rules for v2 work

- **One feature per branch and PR.** Logic goes in `src/utils/` with Jest tests; screens stay thin.
- **Database changes go in a new numbered `supabase/` script**, re-runnable, with a test in `supabase/tests/` when it touches access rules.
- **Private by default.** Every new table gets owner-only row-level security. Anything shareable is published one item at a time, and locations and notes are removed before it's visible to anyone else.
- **The server enforces the rules.** Checks in the app are for convenience; access, sizes and types are enforced by RLS, bucket settings and database functions.
- **No secrets in the app.** Only the anon key ships. Anything needing a private key (the AI advisor) runs in a Supabase Edge Function.
- **Unfinished social features stay behind `SOCIAL_ENABLED`.**
- **Split `app/roll/[id].tsx`** (about 2,300 lines) into components before adding features to it.
- **Update the docs in the same PR** (README, ARCHITECTURE, this file).

## 2. Phase A: workflow (low risk, high value)

| Feature | Notes |
|---|---|
| **Frame order from file names** | Recognise common scanner and lab naming (sequence numbers, `R1-07`, `000123450007`), so scans land on the right frames with fewer manual fixes. Pure function plus tests. |
| **CI** | GitHub Actions runs `tsc` and `npm test` on every PR, so a broken build can't be merged. |
| **Standalone phone app** | EAS development build, then TestFlight. Needs the real icon, a privacy policy and **in-app account deletion** (Apple requires it for apps with sign-up). Unlocks voice logging. |
| **Account deletion** | Deletes the user's rows and scans server-side (Edge Function with the service key), after offering an export. |
| **Resumable uploads with progress** | Supabase's resumable (TUS) uploads for large TIFFs; a byte-level progress bar; survives switching apps. |
| **Share sheet** | Share a scan or a roll's scans to other apps, with an option to strip GPS from the copies. |
| **Split the roll screen** | `app/roll/[id].tsx` into frame list, film strip, development panel and modals. |

## 3. Phase B: AI helpers

| Feature | Rules |
|---|---|
| **Film advisor** | Advice only: which film for a situation, what to improve, shot ideas. It gets a read-only summary of your rolls (stocks, ratings, push/pull, notes you allow) and **no tools that can change data**. Calls go through an Edge Function that holds the API key, checks the user is signed in and rate-limits. No scans or GPS are sent. Opt-in, with a clear note of what's shared. |
| **Voice logging** | Speak a frame's settings ("f8, 125th, overcast"). Speech is recognised **on the device**; only the resulting text is kept and parsed into fields locally. Audio is never stored or uploaded. Needs the standalone build; off on the web. |

## 4. Phase C: sharing and social (decide before building)

Decide first whether this is worth it next to Lomography and Instagram. If yes:

- **Publish one roll or frame at a time**, through a database view that only exposes chosen fields (no GPS, no notes), not by reopening the base tables.
- **Public roll pages** with downloadable scans if the owner allows it, and an Instagram-ready export.
- **Walks and articles**: the existing walks code returns behind `SOCIAL_ENABLED`, reviewed against these rules.
- **Before launch**: reporting and blocking, storage costs for public images, and moderation.

## 5. Security track (runs alongside)

Proportionate zero trust: never trust the app or the network; check every request where the data lives.

- ✅ RLS on every table; sync through field-whitelisted database functions; anon key only; 1-hour signed scan links.
- ✅ `supabase/21`: private bucket, server-side size and type limits, no public reads in v1.
- ❌ Two-factor sign-in for your admin accounts (now) and an optional TOTP second factor for users (Supabase supports it).
- ❌ Supabase's leaked-password protection, if your plan includes it.
- ❌ GitHub secret scanning and Dependabot; review `npm audit` results.
- ❌ Run `supabase/tests/*.sql` in CI against a disposable database.
- ❌ Glance at Supabase's auth and storage logs each month.

## 6. Not planned

- AI analysis of scan images.
- A separate scan-processing service (Go or AWS).
- Buying recommendations beyond simple stats.
- An in-app development timer with background alerts (revisit after the standalone build).
